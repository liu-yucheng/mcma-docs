MCMA mechanism

How it works

Six figures of the loop, the clock, the files, the rollback, the rubric, and the splits.

This page draws the machine, not the code. Each figure answers one question about how the plugin works: what moves in a forward pass, where the clock goes, where a file lands, when the parameters roll back, what the dashboard draws, what one pass learns, and how a rubric becomes one number.

The figures are inline SVG. They inherit the color of this page, so they read the same in the light theme and the dark theme.

1. The training loop

One forward pass makes a product. The Evaluator scores the product. The plugin reduces the score to one loss. The Evolver turns the loss into one plan. A backward pass turns the plan into the next parameters version.

2. Where the time goes

One forward pass fits 720 seconds and one backward pass fits 120 seconds. The pass runs one work stage, never both. The runner gives each stage the smaller of its own limit and the time that the pass has left, so a pass never runs past its budget. A validation pass and a test pass keep the same 720-second budget.

3. Where a file lands

A session writes two kinds of output. The product belongs to the human and lives in the workspace. The training records belong to the loop and live in the app data.

4. When the parameters roll back

A validation pass compares its loss with the best loss that a kept version reached. The comparison uses a tolerance of 0.02. Three worse passes in a row restore the best version.

5. What the dashboard draws

The MCMA tab draws the live state of the loop. It refreshes every 3 seconds, so a running pass shows its stage and its wall clock inside the shortest stage. Four views follow one question each.

6. What one pass learns

A pass now carries the result of the earlier passes into the next attempt. The table names the repair and the failure that the repair removes.

The rubric states anchors of 1, 3, and 5. Two passes scored the same product with two different scales.
A gradient entry names one rubric dimension. The plan could not target the dimension that moved the loss.
A failed stage must lower a score. A crash and a timeout cost no loss, so the loop repeated them.
The evaluator compares the loss with the version that it ran. A version could look better than the version that it replaced.

7. How a rubric becomes one number

Each mode has its own rubric. A dimension scores from 0 to 5. The loss weighs each dimension by its share and turns the score into a penalty, so 0 is a perfect session and 1 is a failed session.
