    dsh-mcma - v0.41.0

    MCMA API documentation

    MCMA is a DeepSeek Harness plugin. It teaches one math problem, or grades one solution attempt, and it learns from its own evaluation of that work. A forward pass runs three stages through isolated subagents. A backward pass turns one evolution plan into one new parameters version.

    Start here

    • Commands: /mcma_forward, /mcma_backward, /mcma_validate, /mcma_test, /mcma_feedback, /mcma_help, and /mcma_clear_appdata. The bare /mcma command prints the syntax. /mcma_help prints the manual with the live state, and /mcma_clear_appdata --yes restores the packaged seed.
    • Tools: mcma_forward, mcma_validate, mcma_test, mcma_backward, mcma_feedback, mcma_status, mcma_help, and mcma_clear_appdata. The plugin registers eight tools and eight commands.
    • Chat interface: one /mcma... line runs in every chat session, including a new empty session. The plugin registers its own / input source, so the line does not depend on the Harness command catalogue. The plugin removes one leading @ from each argument. A forward, validation, or test command also accepts an attached image or file. Ordinary chat text runs through the matching tool.
    • Command row: one command writes one row in the transcript. The row carries the mode, the split, the problem count, one line for each session with its status, loss, and workspace path, the elapsed time, and the app data path. The first command of a session that has no turn starts the first turn, and it writes the session title once.
    • MCMA view: one MCMA tab sits next to Chat, Trajectory, and Git Graph. It reads the read-only route GET /api/dsh-mcma/state and shows the parameters version, the loss of each split, the checkpoint table, the rubric heatmap, and the sessions with the artifact paths.
    • Training loop: configs_rw/ holds the parameters, one problem is one data item, and the Evaluator subagent is the loss function. A loss is the mean of 1 - score / 5 over the rubric dimensions. The Evolver subagent writes the gradient.
    • Stage order: intake, tutoring or grading, self_eval, and self_evolve. The first three stages are the forward pass. The last stage is the backward pass.
    • Splits: a training pass writes evals/pending/, a validation pass writes evals/validated/, and a test pass writes evals/tested/. Only a training pass publishes an evolution plan.
    • Feedback: /mcma_feedback appends supervision to one pending session, re-runs the evaluator, and rewrites the plan. It changes no parameter and no applied version.

    Modules

    Module Role
    index.ts Plugin entry: configuration, tools, commands, and the system prompt section.
    service.ts Orchestrator: passes, policy, history, rollback, and feedback.
    runner.ts One session: stages, retries, products, loss, gradient, and plan.
    subagents.ts Activation of one stage and the timeout guard.
    prompts.ts Stage prompts and the parsing of one stage report.
    evaluation.ts Rubric reduction, the loss value, and the scorecard.
    optimizer.ts Pending plans, change application, and parameters versions.
    paths.ts The app-data layout and the workspace layout.
    config.ts The read-only configuration and the parameters versions.
    uiState.ts The read-only projection for the browser page.
    settingsBridge.ts The nine settings routes and the state route.
    help.ts The command manual and the topic pages.
    inputs.ts Resolution of a command argument into one problem record.

    Style

    The documentation follows the two reference pages that the build renders: the natural language style and the code style. Both pages are in this site.

    Every subagent reads the same two guides from <app_data>/styles/ before it writes. The packaged seed carries a copy, and npm run seed refreshes that copy from the repository .refs/ directory.

    A session writes one product page, report.html, and one code directory, code/, in both modes. The page renders its mathematics with KaTeX from LaTeX source. The code directory holds the Python scripts, code/requirements.txt, and the figures. The Tutor and the Grader create the environment with uv and verify each deduction with numpy, scipy, and matplotlib.
