The nine settings routes and the one state route that the browser half calls.

Browser contract

The plugin has two halves. The host half runs in src/. The browser half runs in client/index.js. The two halves speak over HTTP routes on the Harness web server, and the routes are the only coupling between them.

Routes

The plugin registers nine settings routes and one state route. Each route answers JSON. A reply holds {"ok": true, "value": ...} on success and {"ok": false, "code": "...", "message": "..."} on failure.

Route Method Body Answer
/api/dsh-mcma/describe POST none The settings record.
/api/dsh-mcma/save POST {"appDataRoot": "..."} The settings record.
/api/dsh-mcma/clear POST {"confirm": true} The settings record.
/api/dsh-mcma/reset POST {"confirm": true} The settings record.
/api/dsh-mcma/limits POST {"stageTimeLimits": {"intake": 60}} The settings record.
/api/dsh-mcma/limits-reset POST none The settings record.
/api/dsh-mcma/policy POST {"rollbackThreshold": 3} The policy record.
/api/dsh-mcma/policy-reset POST none The policy record.
/api/dsh-mcma/state GET none The read-only projection.

A stage time limit of 0 means automatic, so the read-only value of rsi.json applies. A rollback threshold of 0 means automatic in the same way.

The settings record names the time budget of a pass:

Field Meaning
budget.forwardBudgetSeconds The wall-clock budget that one forward pass must fit. The value is 720 seconds.
budget.tutoringSeconds The sum of the stage limits of one tutoring pass.
budget.gradingSeconds The sum of the stage limits of one grading pass.
budget.validationSeconds The wall-clock budget of a validation pass. The value is 720 seconds.
budget.testSeconds The wall-clock budget of a test pass. The value is 720 seconds.
budget.backwardSeconds The wall-clock budget of one backward pass. The value is 120 seconds.

The time budget of a pass is also the limit that the runner enforces. The runner gives each stage the smaller of its own limit and the time that the pass has left, so a pass never runs past its budget. A pass that reaches the budget stops, records one pass_timeout intervention, and keeps a resume record for each stage. A human continues it with the mcma_resume command or with the mcma_resume tool.

Resume records

A session keeps one record for each stage that it started:

<app-data>/sessions/<session-id>/resume/<stage>.json

The record holds the status, the interruption kind, the reason, the attempt, and the prompt file of the attempt. A manual interrupt writes the interruption kind manual and no intervention. An automatic failure writes the interruption kind automatic and one intervention. A resume keeps every stage that holds the status ok and runs the stage that stopped.

State projection

The state route answers the projection that the MCMA tab draws. The projection holds the parameters version, the split losses, the loss history, the checkpoints, the scorecards, the sessions, the running session, the pass ledger, and the learning trend.

The pass ledger holds the latest forward, validation, test, and backward passes. One entry holds the kind, the status, the loss, the wall clock, the budget, the share of the budget, the number of kept stages, the interruption kind, and the resume command. A backward pass entry comes from the checkpoint record of the parameters version, because a backward pass writes no session.

The learning trend holds the loss of each pass and a smoothed value of the same split. The browser page refreshes the state every 3 seconds while the tab is visible.

Guards

A route refuses a request that the browser marks sec-fetch-site: cross-site. A route also refuses a request whose origin host differs from the request host. A request body over 64 KiB is refused.

Write scope

A pass writes only below four roots: the current DeepSeek Harness workspace (cws), the problem workspace (pws), the app data of the plugin (ad), and the temporary directories (temp). The problem workspace is the session directory <cws>/<session>/, and its temporary directory is <pws>/.tmp/. The stage prompt moves every cache variable and every managed interpreter into the temporary directory, so a stage needs no write to the home directory.

The runner records the top-level entries of the three durable roots before the first stage. At the end of the pass it deletes <pws>/.tmp/, and it deletes each entry that is new and named in the stray list, such as venv, __pycache__, .cache, or node_modules. It deletes no entry that the record holds, no code/.venv/, and no .git.

Command output

The command cards read the text of one command row. The row holds one line for each pattern:

Mode: <Tutoring|Grading>
Split: <train|validation|test>
Problems: <count>
<sessionId>: <status>. Workspace: <path>
  Problem: <name> | Loss: <value>
Decision: <keep|rollback|baseline>
Verdict: <improved|unchanged|regressed|baseline>
Elapsed: <seconds>s of <budget>s
App data: <path>
Error: <text>

The resume command prints one more line:

<sessionId>: resumed at <stage>. The pass kept <count> stage(s).

A change to one of these lines needs a matching change in client/index.js and in test/mcma.test.mjs.
